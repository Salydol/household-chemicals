# Cleanology — каталог бытовой химии и услуг

Next.js 15 (App Router) + TypeScript + Prisma + PostgreSQL + Tailwind CSS + Auth.js.

Сайт **не интернет-магазин**: нет корзины, оплаты, регистрации и данных покупателей.
Задача — показать продукцию и перевести человека в WhatsApp.

В каталоге два типа позиций, различаются только наличием цены:

- **товары** (бытовая химия, инвентарь) — с ценой, участвуют в сортировке и фильтре по цене;
- **услуги** (клининг, химчистка) — без цены. Везде показывается «Узнать цену»,
  на странице позиции — «Цена по запросу» и кнопка «Узнать стоимость в WhatsApp».

Чтобы позиция стала услугой, достаточно оставить поле «Цена» пустым — отдельного раздела
и отдельной таблицы для услуг нет.

## Быстрый старт (Windows)

### 1. База данных

Вариант с Docker (проще всего):

```bash
docker compose up -d
```

Поднимется PostgreSQL 16 на `localhost:5432`, база `catalog`, пользователь/пароль `catalog`.

Если Postgres уже установлен локально — просто пропишите свою строку подключения в `.env`.

### 2. Переменные окружения

Файл `.env` уже создан. Обязательно поменяйте `AUTH_SECRET` на длинную случайную строку:

```
DATABASE_URL="postgresql://catalog:catalog@localhost:5432/catalog?schema=public"
AUTH_SECRET="длинная-случайная-строка"
NEXTAUTH_URL="http://localhost:3000"
NEXT_PUBLIC_SITE_URL="http://localhost:3000"
ADMIN_EMAIL="admin@site.kz"
ADMIN_PASSWORD="admin12345"
```

`NEXT_PUBLIC_SITE_URL` подставляется в ссылку на товар внутри сообщения WhatsApp —
на боевом сервере укажите здесь реальный домен.

### 3. Установка и запуск

```bash
npm install
npm run db:push     # создать таблицы
npm run db:seed     # демо-данные + администратор
npm run dev
```

Сайт: http://localhost:3000
Админка: http://localhost:3000/admin (логин и пароль — из `.env`)

### Продакшн

```bash
npm run build
npm start
```

## Админ-панель

| Раздел | Что делает |
| --- | --- |
| Dashboard | всего товаров, в наличии, под заказ, скрыто, категорий, последние добавленные |
| Товары | таблица с поиском и фильтрами, добавление, редактирование, скрытие, удаление |
| Категории | добавить, переименовать, изображение, порядок, скрыть, удалить |
| Главная страница | hero, блок «О компании», преимущества, выбор популярных товаров |
| Настройки | компания, логотип, контакты, соцсети, **номер WhatsApp**, показ цен |

Администратор создаётся сидом. Регистрации на сайте нет.
Чтобы добавить ещё одного администратора — через `npm run db:studio` или SQL
(пароль хранится как bcrypt-хеш).

## WhatsApp

Все кнопки «Заказать» и «Написать в WhatsApp» берут номер из **Настройки → WhatsApp**.
Меняется в одном месте.

Сообщение собирается автоматически:

```
Здравствуйте! Хочу узнать подробнее о товаре «Динозавр T-Rex»: https://site.kz/product/dinosaur-trex
```

Базовый текст тоже меняется в настройках.

## Цены

В **Настройки → Отображение цен** два режима:

- **Показывать цены** — цена видна в каталоге и на странице товара, доступна сортировка по цене и фильтр по цене;
- **Не показывать** — вместо цены везде «Узнать цену», сортировки и фильтра по цене нет.

Значение цены при этом всё равно хранится в базе.

## Изображения

Загружаются через админку в `public/uploads` (до 8 МБ, jpg/png/webp/gif/svg).
Первое фото товара — главное.

Куда именно сохранять — решает переменная `BLOB_READ_WRITE_TOKEN`:

- **не задана** — файлы пишутся в `public/uploads`. Так работает localhost и свой сервер (VPS, Docker);
- **задана** — файлы уходят в Vercel Blob. На Vercel это единственный рабочий вариант:
  файловая система там доступна только для чтения, запись на диск молча теряется.

Переключение автоматическое, менять код не нужно.

Если понадобится Cloudinary или S3 — правится только `src/app/api/upload/route.ts`:
он должен вернуть `{ urls: [...] }`, остальной код не трогается.

## Чек-лист перед публикацией

## Миграции базы

`npm run db:push` удобен на этапе разработки: он просто приводит базу к схеме.
Как только сайт заработает на боевом сервере, переходите на миграции —
они версионируются и не теряют данные:

```bash
npx prisma migrate dev --name init     # создать миграцию локально
npx prisma migrate deploy              # применить на сервере
```

## Известные ограничения текущей версии

- Фото сохраняются как есть, без сжатия и превью — не загружайте снимки по 8 МБ,
  либо добавьте обработку через `sharp` в `src/app/api/upload/route.ts`.
- При удалении товара его файлы остаются в `public/uploads`.
- У формы входа нет ограничения на число попыток.
- Загрузка SVG разрешена (удобно для логотипа). SVG может содержать скрипт,
  поэтому грузите только свои файлы. Если это смущает — уберите `image/svg+xml`
  из списка `ALLOWED` в `src/app/api/upload/route.ts`.

## Как заменить демо-контент

Демо-данные лежат в `prisma/data.ts` — категории, товары, услуги, тексты главной и настройки.
Файл читается двумя командами:

- `npm run db:seed` — добавляет то, чего ещё нет в базе, существующее не трогает;
- `npm run db:reseed` — **удаляет** все товары, категории, преимущества, настройки и контент
  главной, затем заливает содержимое `data.ts` заново. Администраторы не удаляются.

Второй вариант нужен, когда в базе остался контент от прошлой темы сайта.

Заглушки-картинки лежат в `public/uploads/demo`. Когда загрузите настоящие фото через админку,
эту папку можно удалить целиком — на неё ссылаются только демо-данные.

# Деплой на Vercel

## 1. GitHub

```bash
git init
git add -A
git commit -m "Cleanology: каталог и админка"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/ИМЯ_РЕПО.git
git push -u origin main
```

`.env` в репозиторий не попадает — он в `.gitignore`. Все секреты задаются в настройках Vercel.

## 2. Импорт в Vercel

New Project → Import Git Repository → выбрать репозиторий.
Framework Next.js определится сам, команду сборки менять не нужно.

## 3. Переменные окружения

Добавить в Settings → Environment Variables (для Production, Preview и Development):

| Переменная | Значение |
| --- | --- |
| `DATABASE_URL` | строка Neon **через пулер** — с `-pooler` в хосте |
| `DIRECT_URL` | строка Neon **прямая** — без `-pooler` |
| `AUTH_SECRET` | длинная случайная строка |
| `NEXT_PUBLIC_SITE_URL` | адрес сайта, например `https://cleanology.vercel.app` |

Почему две строки подключения. На Vercel каждый запрос поднимает отдельный экземпляр функции,
и каждый открывает своё соединение с базой — прямых подключений на это не хватит.
Пулер держит их за вас. Но `prisma db push` и миграции через пулер не работают,
поэтому им нужна прямая строка — это и есть `DIRECT_URL`.

Строку с пулером берите в Neon: Connection string → **Pooled connection**.

## 4. Хранилище фотографий

В проекте Vercel: Storage → Create Database → **Blob** → Connect.
Переменная `BLOB_READ_WRITE_TOKEN` подставится сама, ничего копировать не нужно.

Без этого шага загрузка фото в админке будет отдавать ошибку.

После подключения Blob сделайте Redeploy, чтобы переменная попала в сборку.

## 5. База

Схема уже применена к базе Neon командой `npm run db:push` — на Vercel ничего мигрировать не нужно.
Данные общие: что вы добавите через локальную админку, появится и на боевом сайте, и наоборот.

Когда сайт заработает, переходите на миграции вместо `db:push`:

```bash
npx prisma migrate dev --name init
```

## 6. После первого деплоя

- Поставьте реальный `NEXT_PUBLIC_SITE_URL` и сделайте Redeploy — иначе в сообщения WhatsApp
  будут уходить ссылки на `localhost`.
- Смените пароль администратора.
- Проверьте загрузку фото в админке боевого сайта.

## Что учесть

Страницы рендерятся на каждый запрос (`force-dynamic`), поэтому изменения из админки видны сразу,
без пересборки. Обратная сторона — каждый заход дёргает базу.

База Neon на бесплатном тарифе засыпает после нескольких минут простоя, и первый запрос
после паузы идёт 2–3 секунды. На посещаемом сайте это незаметно, на пустом — первая загрузка
будет подтормаживать.
